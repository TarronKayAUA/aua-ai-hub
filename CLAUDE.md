## Non-negotiable working rules

1. Never hardcode data values that should come from a source file or feed. News, videos, and podcasts come only from the pipeline; the conference table only from data/conferences.yaml; the tools directory only from data/tools.yaml, and its task chooser's vocabulary only from data/tool_tasks.yaml (membership is derived from tools.yaml, never listed by hand); the open-weights models section only from data/open_models.yaml; the prompt library only from data/prompts.yaml and its learning resources only from data/prompt_resources.yaml; the setup-video lists only from data/guide_videos.yaml; the Courses and Resources cards only from data/learning_resources.yaml; feed rosters and LLM endpoints/models only from feeds.yaml. If you are about to paste a value into a page or script, stop and wire the data path instead.
2. After any multi-item generation step, print verification counts: inputs read, items kept and dropped, files written. Cross-check totals and fail loudly on mismatch.
3. Before declaring any feature complete, check it against SPEC acceptance criteria and state which criteria were verified and how.
4. Verify external facts instead of guessing. Every feed URL is fetched and parsed before committing (scripts/verify_feeds.py). Conference dates that cannot be confirmed from an official source are written as TBD, never invented. The conference-watch workflow (auto mode since 2026-07-01) may apply a calendar change itself only when it passes every gate: the extraction is grounded in the fetched official page, the dates stay coherent, and the value was stable across two consecutive runs (state in data/conference_watch_state.json, pipeline-owned, never hand-edit). Applied lines carry an auto-verified provenance comment; gate failures become issue proposals; new conferences are always propose-only. Library APIs, endpoints, and model identifiers are checked against current documentation, not training memory.
5. Errors in this project are costly to the owner. Prefer a smaller verified step over a larger unverified one.

## Published content style

These rules apply to everything rendered on the site, including pipeline-generated summaries:

- No em dashes anywhere in site copy. Use commas, periods, colons, or parentheses instead. The pipeline post-processes LLM output to enforce this; check generated output too.
- Plain language for medical educators and students. Expand acronyms on first use per page. US English.
- Neutral tone. No hype, no vendor editorializing, no superlatives in news summaries.
- Governance statuses in the tools directory describe the institution's relationship with a tool (listed | licensed | reviewed | caution | restricted; reframed 2026-07-14 from the review-pipeline vocabulary, owner approved). A listing is not an endorsement, and committee review is request-driven. Review statuses in the prompt library remain provisional until the AI Committee ratifies them, and that provisional framing stays. Only the owner changes statuses in either file.
- Authority register (owner preference, 2026-06-12): status language describes where material is in its process, never an endorsement the owner grants. Authority is attributed to the AI Committee and the policy, not to the Associate Dean (Assistant Dean when this preference was recorded; the rule is about the role, not the rank); the role appears as maintainer and contact point only, always without "Office of the". Everything stays modest; patient and student-record privacy is the policy's to state, and site copy links it rather than restating it (2026-09-26).
- Policy register (owner direction, 2026-09-23, from the caution-tape audit recorded in SPEC section 12): the published AI Responsible Use Policy is the only rulebook (since 2026-09-26 the site links it instead of restating its requirements; see the next bullet). Everything else is a suggestion or best practice with a concrete reason (accuracy, quality, protecting a patient or student, respecting someone's work, a licensing fact), not a rule. No red or amber boxes for policy points; alarm styling is for practical hazards only. Library prompts carry no data restrictions; practical tips about what to leave out live in page copy, framed as the next bullet says. Unenforceable rules push people to hide their use, so do not add new ones.
- Color by meaning (owner decision, 2026-09-26): each hue means one kind of page everywhere (tool, prompt, guide, lesson, benchmark, news and events, governance; rose reserved), assigned through `kinds:` in data/section_map.yaml and the palette block in docs/stylesheets/layout-nav.css, never by position or section. Every place the colors appear carries the quiet "Color key:" line listing only the kinds drawn there. Color never carries meaning alone, and colored text is checked on its own tint as well as the page. No page shows Material's left sidebar or right column: navigation is scripts/layout_nav.py's floating controls and page feet (SPEC section 12).
- Reading pages use the full frame (owner decision, 2026-09-26): scripts/layout_width.py arranges every task, lesson and reference page from its own structure (panels in thin outlines, two-column spreads that fit one screen, a paragraph beside its figure, a heading always with what it introduces), every line one 31rem measure. Do not restore the single centred 33rem column, and do not remove the panel outlines for calm: the owner chose them because large blank areas are what he wants gone. "Browse" and "On This Page" are one bottom-left control on every page (landing pages included) that folds after about 4 seconds, animated, to a compass with the word "Navigate" (mkdocs.yml `extra: nav_control_label`); hover, focus or a tap reveals it.
- Policy as the one reference point (owner direction, 2026-09-26; the owner drafted the policy himself): the ratified AI Responsible Use Policy, in its original wording, is the only place on the site where restrictions live. Site copy does not restate or enforce its rules and adds no restrictions of its own, because they cannot be enforced; it links to the policy where a reader needs it, and it never encourages anything that contradicts it (for example, never say or imply that putting your own unpublished research into a public AI tool is fine). Where the site explains caution (Module 3 is a light-touch guide to the policy), it gives the reason in the reader's own interest, so what we ask them to give up reads as a net benefit to them, never red paint and caution tape. Practical how-to tips (strip a case to an age band and a presentation pattern before practising, leave names out of an essay before asking for feedback) stay, framed as doing the task well, with the reason and no rule language. In site copy the approving body is "the AI Committee": the policy's "AI Responsible Use Subcommittee" is the AI Committee in practice (the verbatim policy page keeps its own wording).
- Title case (owner decision, 2026-09-27): titles, headings, names and labels are Chicago-style title case: page titles, nav labels, section headings (h2 to h4), card titles, prompt titles, category names and short labels, group names, and audience tags ("Faculty", "Students", "Faculty & Students", "Everyone", never "For faculty"). Buttons, body text, descriptions, taglines, subtitles and figure titles stay sentence case, except the corner navigation control, whose labels and panel titles are title case ("Browse the Site", "On This Page"; owner, 2026-09-28). Excluded: the verbatim policy page, pipeline-generated pages and includes, news headlines, and publishers' own names (tools, models, leaderboards, courses, papers, conferences), which keep their owners' spelling. A specific prompt or page named in running text takes its title's capitals; the prompt text itself is never touched. scripts/title_case.py (a build hook, registered last) checks it in the final HTML (row and card link titles included, external and button-style links left out by rule) and the data files and fails the build on a violation; add to its EXEMPT list only a reviewed name spelled by its owner. A heading change on a narrated page makes its recording stale (the narration reads every heading), so it needs a local re-record. Ordering (same date): where kinds are listed together, logical order first, otherwise guides, then lessons, then prompts, then tools (`order:` in data/section_map.yaml drives the generated lists).
- Design language (2026-09-27): DESIGN.md at the repository root is the design reference every new page, section and data-driven list follows (layout, components, color, case, checklists, things not to do, gaps left on purpose). Run `python scripts/design_check.py` (authoring only, not CI; system Python with Playwright, like figure_sheet.py) before a layout change ships, and refresh its baseline (`--only measure --update-baselines`) only after the owner approves a change. Art follows DESIGN.md section 19 (the owner's quality bar and the method that meets it); render a piece with `python scripts/art_review.py` before he sees it.

## Stack and commands

- Python 3.11+ (this machine has 3.13 in `.venv\`; run everything as `& ".venv\Scripts\python.exe" ...`). Dependencies pinned in requirements.txt. Pillow is an authoring-only extra for scripts/build_brand_assets.py, deliberately not pinned.
- Local preview: `mkdocs serve`. Validation build: `mkdocs build --strict` (run after any nav or content change; CI gates deploys on it).
- Pipeline dry run: `python scripts/aggregate.py --dry-run --verbose` (always dry-run first and review the verification block before any write-mode run). LLM curation needs GITHUB_TOKEN (GitHub Models) or ANTHROPIC_API_KEY in the environment; without either it falls back to keyword mode and says so in the verification block.
- Narration: two engines, both configured in the feeds.yaml `narration` block and never hardcoded. Static pages (9) use Speechify simba-3.2 (`wyatt_32`), metered, run locally only; the news briefs use Kokoro locally and in CI. `--dry-run` lists what would be (re)generated and what it would cost, `--check` exits 1 on stale static audio, `--voices` lists the voices the configured model supports (most of the catalogue is simba-3.0 only, so a voice/model mismatch is caught before it can silently downgrade). The Kokoro path needs `requirements-narration.txt` in Python 3.10 to 3.13 (kokoro-onnx does not support 3.14) and downloads the 337 MB model once into ~/.cache/aua-narration; the Speechify path needs `SPEECHIFY_API_KEY` or `%USERPROFILE%\.aua-narration\speechify.key`, which must NEVER become a GitHub secret. Use `--only static` locally; a bare run also builds the Kokoro engine. **CI can no longer self-heal static narration** (that was true 2026-09-02 to 2026-09-03 only): edit a narrated page without regenerating and the build hook serves that page with NO player rather than superseded audio, and narration-health.yml opens an issue. Sidecar hashes cover engine identity as well as text, so a voice change re-reads exactly the affected pages. Metered spend is ledgered in data/narration_spend.json against `narration.monthly_char_budget`; the guard refuses a run that would exceed the remaining allowance, and refuses if the ledger is unreadable rather than assuming an unspent month.
- Figures: new figures put their words in HTML and draw only shapes (the `.hf-*` vocabulary in extra.css, SPEC section 12), because a single-SVG figure scales its text with the drawing and was 4 to 6px on phones. Before shipping a figure, run the authoring-only `python scripts/figure_sheet.py` (needs playwright and Pillow, which the system Python here has, not the venv): it renders every figure at 1440 and 390px in both schemes, writes contact sheets, and exits 1 listing any figure whose smallest text is under 11px. Since 2026-09-23 every figure passes (all 44 rebuilt, words in HTML); a figure it lists is a regression. It is an authoring check, not a CI gate.
- Checkers: `python scripts/verify_feeds.py` (all feeds; a feed carrying `expect_fail_in_ci` in feeds.yaml is known-blocked from Actions IPs and kept failing soft with a replacement already in the roster, so it is tolerated rather than raised. The alert is inverted for those: the actionable event is one of them WORKING again, which means the block lifted and its replacement can be retired. Recovery only counts inside CI, since they pass from an ordinary network. Exit code means "a human must act", not "a feed failed"), `python scripts/verify_links.py --all-docs` (all links), `python scripts/conference_watch.py --propose-only` (conference proposal report; the flag matters, because a bare run honors the feeds.yaml `conference_watch.mode`, auto since 2026-07-01, and with an API key present can write data/conferences.yaml and the watch state, consuming a stability-gate run).

## Hard-won gotchas

- GitHub Models free tier rejects requests over 8,000 tokens; candidate payloads are budget-packed under `max_payload_chars` in the feeds.yaml llm block. The curation model sometimes mislabels categories, so media curation calls treat any keep as that call's media type.
- GitHub Actions does not expose GITHUB_TOKEN as an env var automatically; workflow steps that need it must set `env: GITHUB_TOKEN: ${{ github.token }}` or curation silently falls back to keyword mode.
- Pushes made with the default GITHUB_TOKEN do not trigger other workflows; refresh.yml builds and deploys itself after committing.
- PubMed and amia.org return 403 to all scripted clients; PubMed RSS URLs are owner-generated through pubmed.gov's Create RSS flow. gamma.app 403s scripts but is live (allowlisted in verify_links.py). YouTube channel ids must come from a channel page's canonical link, not the first channelId in the page source. Podcast RSS URLs resolve reliably through the Apple Podcasts directory API.
- PowerShell 5.1 `Set-Content -Encoding utf8` writes a BOM; restore files with `git checkout --` rather than round-tripping, and use `git commit -F <file>` for multi-line commit messages. Write the message file with a BOM-free tool (a BOM corrupted the subject of commit e0bf7e6). PowerShell `Select-Object -First N` closes the pipe early and makes the upstream command report failure (a passing `mkdocs build --strict` showed exit 255 this way); check the build's own output, not the chain's exit code.
- The weekly digest fires on the UTC Friday, which is Thursday evening local. To regenerate a week's digest (selection and narrative rerun, archive page overwritten under the same guid): clear `last_digest_week` and `last_digest_at` and drop that week's entry from `digests` in data/seen_items.json, via a one-time script that prints before/after state. The narrative is skipped on dry runs because the call is paid.
- A full `verify_links.py` sweep exceeds a 10-minute foreground window; run it in the background. Media curation is one-shot: a dropped video or news item is recorded as seen and never re-offered, so prompt changes are forward-looking unless specific ledger entries are flipped or un-seen by hand (exactly-once-checked scripts only).
- LiveBench's app bundle stopped labeling releases with a "LiveBench-" prefix (noticed 2026-07-13 after weeks of silent fallback to a stale pinned table). Discovery now probes every date-like bundle token against table_{date}.csv newest-first, so the data endpoint is the source of truth; if the table ever goes stale again, check whether the bundle URL pattern itself changed.
- A markdown link destination may legally contain balanced parentheses, and Python-Markdown renders them, so a checker regex ending the destination at the first `)` reports a verdict about a URL the site never links. That was issue #46: HTTP 403 for `.../S0960-9822(26`, a string absent from the built site, while the real Cell citation beside it had never once been fetched (2026-09-05). verify_links.py now walks destinations with a depth counter, proves it against LINK_CONTROLS at import (the BLOCK_CONTROLS idiom), and asserts the per-file destination count against a separately-counted opening count. Do not simplify that back to a regex balancing one level: on a nested destination it matches nothing at all, which is a silently skipped link rather than a wrongly checked one. Note also that the reflex remedy would have been worse than the bug, because the truncated string's host is still cell.com and a MANUALLY_VERIFIED entry would have green-lit the phantom permanently while the real link stayed untested. Fix an extractor before allowlisting anything it produced.
- `status < 400` is not evidence a link is alive. A survey of every host this site links (2026-09-05, 135 hosts) found 30 that answer 200 for a path that cannot exist, though about twenty are moot because only the bare domain root is linked and a root has no id to rot. Two shapes are registered in `SOFT_404_SHAPES` with a discriminator and a canary: the feedback form's `forms.office.com/r/` shortlink, linked from 13 pages, and `arena.ai/leaderboard/`. The rest are deliberately excluded and the reasons are written beside the table, because the refusals are the valuable half. AAMC especially: its 200 is an Akamai bot challenge byte-identical for live and dead URLs that landed on live pages in the survey's own sample, so any detector for it would report a quarter of live AAMC links dead every month, on an institution the owner works with. Two traps worth keeping: a Forms canary must REPLACE the shortlink code, not extend it, because a suffixed code still resolves to the real form; and a redirect to a sign-in page means an auth wall, which sits in front of live URLs as readily as missing ones.
- Microsoft Forms cannot be checked for closure, and the feedback form is linked from 13 pages. Probed 2026-09-07 by fetching a throwaway form before and after toggling "Accept responses" off: status, final URL, title and body size were identical, because Forms is a JavaScript app that fetches its open/closed state after load and the served HTML carries no state field. So the `SOFT_404_SHAPES` entry catches a DELETED or re-issued form and nothing else. The operational consequence, which matters more than the code: when retiring that form, delete or re-issue it rather than closing it to responses, or update the 13 links in the same sitting. Closing it silently leaves 13 healthy-looking links pointing at a dead end. Related: Microsoft is migrating Forms to `forms.cloud.microsoft`, the Copy link menu hands out the new domain, and both domains are registered because the table keys on the host as written, not the host a link lands on.
- Both health workflows grep their own report to build the issue body, under the Actions default `bash -e`. An unguarded grep that matches nothing aborts the step before the issue is written, so a checker that CRASHED files nothing at all while a checker that merely found failures files normally: the louder problem becomes the quieter one. feed-health.yml got `|| true` in 13db884; link-health.yml got it, plus a separate "checker failed to run" issue shape, on 2026-09-05. Any new health workflow needs the same two guards.
- LLM prompt contracts: models copy example values verbatim. An example drop reason left in the curator output contract ("title is rumor-framed") silently overrode the rule forbidding title-based drops (2026-07-14). Keep every example in a schema or contract consistent with the rules above it.
- Raw HTML indented inside a `???` admonition goes through markdown inline processing, unlike top-level raw HTML blocks: paired `*`/`_` or link-shaped text inside card summaries renders as emphasis/links there but stays literal on uncollapsed pages. Live since the tools-directory collapse; harmless for LLM-written summaries, but if it ever bites, neutralize the characters at render time rather than escaping (escapes leak on the raw-HTML pages).
- MkDocs rewrites markdown link/image paths but NOT raw HTML src/href. With directory URLs, a page at docs/news/foo.md serves from /news/foo/, so raw HTML referencing docs/assets needs ../../assets (the briefs banner bug, 2026-06-11). External SVGs referenced via img cannot read the page's CSS variables, so site artwork under docs/assets is self-contained-color.
- Video candidates with an empty description (a stream that was live at fetch time) are deferred, not judged: they stay out of the ledger and re-enter once the VOD description exists, or after `defer_hours` (feeds.yaml videos block, default 72) title-only, so the one-shot ledger never burns an unassessable video (2026-07-16). Cross-run video dedupe is deliberately URL-only: recurring shows reuse exact titles for distinct streams (both July 15 "AI NEWS LIVE" entries hashed identically), so restoring title-hash dedupe for videos would silently block every later installment of such a show. News and podcasts keep title-hash dedupe.
- GitHub Models was fully retired on 2026-07-30 (playground, catalog, inference API, and BYOK all gone per its docs). The section briefs, the last task on that free tier, moved to claude-sonnet-5 via llm.tasks.section_briefs the next day; the llm.github_models block and the docs' free-tier references are historical until the next documentation sweep. If a workflow ever reports HTTP 410 from models.github.ai, this is why, and the fix is the per-task Anthropic path, not a retry.
- Claude 5 generation models spend thinking from the same max_tokens budget as the visible reply, and the pipeline's default ceiling is 4000: the content-watch synthesis (big payload, long thinking) hit it twice, surfacing as JSONDecodeError with no hint of the cause (issues #20 and #27; fixed 2026-07-28 with a 16000 ceiling for that task and a named truncation error in content_watch.call_task via aggregate's LAST_ANTHROPIC_STOP). Other Sonnet 5 tasks still ride the default; if an LLM JSON task starts failing with JSONDecodeError, check for stop_reason max_tokens before blaming the model's formatting, and remember the request timeout must be long enough for the raised ceiling to be generatable.
- **Pending model re-evaluation, recorded 2026-09-22: re-run it when Sonnet 5.5 or Haiku 5.5 ships** (Anthropic announced both for "the coming weeks" at the Opus 5.5 launch). The owner asked for every pipeline model, not only the Opus ones, to be weighed on price against performance, keeping the cheapest viable model for simple tasks. One thing switched after a blind side-by-side the owner judged: the digest narrative moved from Fable 5.1 to Opus 5.5. The per-tier reasoning is recorded above `llm.tasks` in feeds.yaml, with a pre-swap checklist. The owner's plan for the Haiku 4.5 tasks is to move them to Haiku 5.5 after those checks; the one most likely to bite is the max_tokens ceiling in the bullet above. Two things not to "fix" on the way: the `claude-opus-5` fallback slots stay on Opus 5 because that is where Anthropic itself routes biology refusals from Fable 5.1 and Opus 5.5, whose classifiers they would otherwise share; and a vendor launch table is not the whole evidence, since independent LiveBench puts Fable 5.1 ahead of Opus 5.5 on Language and instruction following, which is what the digest narrative tests.
- A curation model can also DROP what it does not recognize. Through September 2026 Haiku 4.5 dropped real launches (GPT-6 Astra tests, a GPT-6 Luna test, The Verge's dots story) as "speculation about unreleased model"; a backtest on 2026-09-29 found a prompt rule, longer video text, and the run date with the site's tracked names all failed to fix it, so curation moved to Sonnet 5.5 at low effort until Haiku 5.5 (details above `llm.tasks` in feeds.yaml). Before any curation model or prompt change, rerun the backtest: dispatch model-compare.yml with task curation (about $1 per version at three samples) and score it against the labelled fixture in scripts/backtest/.
- A curation model can "correct" a name it does not recognize. On 2026-09-22 Haiku 4.5, whose knowledge ends in February 2025, rewrote "Claude Opus 5.5" as "Claude Opus 3.5" in both the display_title and the summary of a published video card, while three other Opus 5.5 items that day came through intact, so it is intermittent and a spot check usually looks clean. Fixed by an exactly-once, two-field ledger edit; the pages re-render from the ledger on the next refresh. Since the same day, `ungrounded_names` in aggregate.py rejects any curator summary, media title, section brief, or narrative that gives a name a different number than its source does, and lists each rejection in the verification block (SPEC section 9). Its scope is deliberately narrow, so a version the source never states can still get through: check launch-week items by name.

## Process

- For any new feature or structural change, present a short plan and wait for approval before writing code. Routine maintenance covered by the README playbook needs no plan.
- Issue triage sessions (acting on the automation's GitHub issues) follow .claude/commands/triage.md, invocable in Claude Code as /triage; the file is self-contained instructions for any model.
- A monthly tool-discovery survey runs as a Claude Code scheduled task (user-level, outside this repo: C:\Users\TarronKay\.claude\scheduled-tasks\monthly-tool-discovery-survey\SKILL.md, cron 9:00 on the 15th). It is propose-only: it files a "Tool discovery YYYY-MM-DD: N candidates" GitHub issue for the owner, never edits rosters. If the harness running it lacks the Workflow tool its SKILL.md references, run the hunters sequentially; the output contract is the issue, not the method. That contract is now enforced from this repository by .github/workflows/discovery-guard.yml, which runs on the 17th and 24th and files an issue if no "Tool discovery YYYY-MM" issue exists for the month. It checks for the artifact rather than the task's status, because the 2026-08-15 run stopped partway, filed nothing, and was still recorded as succeeded: it went unnoticed for a month, and only surfaced when someone asked why August had no issue. A task's own exit status does not establish that it did its job.
- When SPEC.md and the code disagree, surface the conflict. Do not silently change either one.
- Design and art work with the owner (learned over the September 2026 rounds): he reviews by eye in the local preview and in screenshots at 1920x1080, and catches what scripts miss (misaligned columns, a fold that cannot be closed, jump links that land in one place, a building over water), so look at every visual change yourself at 1920 and 1440 in both schemes before showing him. Quote every new label back to him exactly. Present anything beyond what he asked for (a panel, art, a restyle) as for his decision, built so it can be backed out in one step, and say how. He prefers keeping a feature and fixing it to removing it, and wants every existing function kept through a redesign. Stage work on a branch and merge only after his yes; run long sweeps (the full design check, a full link check) in the background, once per change.
- Work in small steps with verification after each. Do not chain multiple unverified changes.
- When uncertain about anything external (a feed URL, a schema, a current model id, a conference date), check rather than guess.
